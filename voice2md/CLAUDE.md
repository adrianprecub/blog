# CLAUDE.md — repo orientation for the next agent

## What this is

A macOS 14+ menu-bar app written in Swift / SwiftUI. Watches an input folder, transcribes any media file dropped there (audio or video), and writes a Markdown note to an output folder. Source filename → kebab-case slug → `YYYY-MM-DD_HHMM_<slug>.md`.

Transcription source priority:
1. **Apple-embedded transcript** read from the `.m4a`'s MP4 atom path `moov/trak/udta/tsrp` (instant, no model load) — see `Voice2MD/Core/AppleTranscriptExtractor.swift`.
2. **Local `whisper.cpp`** (`whisper-cli` + `ffmpeg` shelled out via `Process`) — see `Voice2MD/Core/Transcriber.swift`. Whisper model `.bin` downloaded in-app to Application Support.

AI extraction is **optional and off by default**. When the user toggles it on, the transcript is sent to one of three pluggable providers — all conform to `AIExtractor` (defined in `Core/AIProvider.swift`):
- `ClaudeClient` — `https://api.anthropic.com/v1/messages` with `cache_control: ephemeral` on the system prompt.
- `AzureOpenAIClient` — `{endpoint}/openai/deployments/{name}/chat/completions?api-version=…` with `response_format: json_object`.
- `OllamaClient` — `{endpoint}/api/chat` with `stream:false`, `format:json`, `num_ctx:8192`. No API key needed.

The renderer has two modes (both pure functions in `Core/MarkdownRenderer.swift`):
- `renderPlain(transcript:media:source:…)` — frontmatter (8 keys) + `# Title` + transcript verbatim. Default mode.
- `render(extraction:media:source:…)` — frontmatter (10 keys) + Summary / Key Ideas / Topics / Action Items / Entities / Cleaned Transcript sections. AI-mode only.

## Build, test, run

The Xcode project is **generated by [xcodegen](https://github.com/yonaskolb/XcodeGen) from `project.yml`**. Don't hand-edit `Voice2MD.xcodeproj`; it's gitignored and recreated on demand.

```sh
# One-time setup
brew install xcodegen whisper-cpp ffmpeg

# After adding or removing files
xcodegen generate

# Build
xcodebuild -project Voice2MD.xcodeproj -scheme Voice2MD -configuration Debug build

# Run all tests
xcodebuild -project Voice2MD.xcodeproj -scheme Voice2MD -destination 'platform=macOS' test

# Run a specific test class
xcodebuild -project Voice2MD.xcodeproj -scheme Voice2MD \
  -destination 'platform=macOS' \
  test -only-testing:Voice2MDTests/PipelineTests
```

To run the app: open in Xcode and ⌘R, or `open ~/Library/Developer/Xcode/DerivedData/Voice2MD-*/Build/Products/Debug/Voice2MD.app`. The waveform icon appears in the menu bar — there's no Dock icon (`LSUIElement=YES`).

## Conventions

**Commits:** Conventional Commits, no scope (e.g. `feat: add re-process missing files menu item`). One feature/fix per commit.

**Testing strategy:** every component is testable in isolation.
- HTTP clients (`Claude`, `Azure`, `Ollama`) take an injectable `URLSession` and are tested against `MockURLProtocol` (defined once in `ClaudeClientTests.swift`, reused everywhere). Use the existing `ConcurrentCounter` helper for retry/repair tests.
- `MarkdownRenderer` is a pure function — golden-file tests with explicit fixed dates + `TimeZone(identifier: "UTC")` for determinism.
- `AppConfig.init(defaults: UserDefaults = .standard)` accepts an injectable `UserDefaults` so tests don't clobber the developer's real settings — always pass an ephemeral suite in tests.
- `Keychain` reads/writes are account-parameterized; tests use `"test-roundtrip-\(UUID())"` accounts to avoid touching real keys.
- Live integration tests (`TranscriberIntegrationTests`, `OllamaIntegrationTests`) **auto-skip** when their dependency isn't installed/running — never fail in CI without the dep.

**No emoji in code, prompts, or commits** unless the user explicitly asks. Apply globally.

**Concurrency:** `AppCoordinator` and the UI are `@MainActor`. `Pipeline`, `ProcessedStore`, `Transcriber` are `actor`s or `@unchecked Sendable` classes. Watcher uses a serial DispatchQueue + `AsyncStream<URL>` to bridge FSEvents into Swift Concurrency.

**Lenient extraction JSON:** `ExtractionResult` / `ActionItem` / `Entities` have custom `init(from decoder:)` that treats missing keys as empty defaults. Smaller local models routinely omit empty sub-fields; do not tighten this without ensuring all three providers still parse real-world output.

## Gotchas

- **`xcodegen generate` after touching the Swift file tree.** Otherwise Xcode won't see new files (and tests won't even compile in the new file).
- **Menubar windows need `NSApp.activate()` before opening.** `LSUIElement` apps don't auto-foreground their windows; without activate, Settings opens behind whatever app is in front. See `MenuBarView.swift` Settings button.
- **Apple's embedded transcript JSON has multiple shapes.** `parseTsrpPayload` handles both `{"attributedString":{"runs":[...]}}` and `{"attributedString":"text"}`. iPad Voice Memos may also write a `tsrp` atom with empty `attributedString` — that returns nil and falls through to whisper.
- **Whisper context window.** `OllamaClient` sets `num_ctx: 8192` because Ollama's default 2048 truncates the system prompt + transcript + JSON output mid-stream. Don't drop this.
- **No code signing for local dev** (`CODE_SIGNING_ALLOWED: NO` in `project.yml`). Launch-at-Login via `SMAppService` shows "Requires approval" until the user enables in System Settings.
- **`processed.json` short-circuits the pipeline by sha256.** If you're testing a re-process flow, set `Pipeline.Inputs.forceReprocess = true` (default false). The Re-process Missing menu item uses this.
- **Whisper model download is real network** in `WhisperModelManager.download(_:)`. Don't trigger it in unit tests; tests use `URLSession.bytes`-mocked downloads or skip.

## Adding a feature: typical playbook

1. Read `app-plan.md` (the original phase-by-phase plan, kept as a historical artifact) and the latest commits to understand the architecture.
2. Plan the smallest concrete change. New AI provider? Add a `Foo: AIExtractor` in `Core/`, route in `AppCoordinator.makeInputs`, branch `AIProvider` enum, drop a section into `AISettingsView`. New transcription source? Plumb through `Transcriber.transcribe()` before whisper falls back.
3. Tests first when possible — golden file for renderer changes, `MockURLProtocol`-stubbed for HTTP.
4. `xcodegen generate` after adding files.
5. `xcodebuild test` until green.
6. Single Conventional Commit. Multi-line body explaining what + why is welcome and consistent with existing log.

## What this app deliberately doesn't do

- No App Store, no notarization, no hardened runtime — local-build only. Easy to add later.
- No multi-language transcription. English-only system prompt; whisper is hard-coded to `-l en`.
- No speaker diarization. `whisper.cpp` produces a single transcript stream.
- No automatic upload to a wiki. The user copy/pastes or `rsync`s the output folder.
